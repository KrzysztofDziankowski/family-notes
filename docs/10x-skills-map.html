10x Skills Map

Every skill in the 10xDevs toolkit, the file it produces, and the files it reads. Everything lives under context/. foundation/ holds project-wide documents, changes/{id}/ holds one unit of work, and archive/ holds finished changes, which no skill writes to.

1 · Foundation pipeline

The idea becomes a PRD. The PRD forks into a greenfield or brownfield track, and both tracks feed the roadmap. Quality gates and agent rules sit beside the pipeline.

2 · The change chain

One folder per change: context/changes/{id}/. change.md stores the status and plan.md ## Progress stores step-level progress. Every skill reads lessons.md as prior knowledge, and three skills also update the matching item in roadmap.md.

3 · Status writes

Each change in change.md status comes from one skill. The skills record status but do not enforce the order, so any step can be skipped. /10x-status flags gaps, such as a plan_reviewed status with no review file. The roadmap item for the change follows the same path: planning after /10x-plan, in-progress after /10x-implement, and done after /10x-archive.

  implemented --> impl_reviewed : /10x-impl-review
  implemented --> archived : /10x-archive
  impl_reviewed --> archived : /10x-archive
  archived --> [*]

Rules every skill follows

Archive is read-only

Every skill that writes refuses a path starting with context/archive/. Reopen work with /10x-new.

Progress is the single source of truth

The ## Progress section of plan.md is the only progress record, with no state files. implement and tdd tick its boxes and add commit SHAs. status and archive read it.

Old versions are kept

When a foundation file already exists, the skill asks whether to overwrite it, save a -vN.md copy, or move the old file to foundation/archive/.

Plans don't cover multiple changes

roadmap.md splits work into slices and plan.md plans one change. The two connect through the Change ID.
